# Qalam Studio: notes for coding agents

- **UI:** a React single-page app built with Vite. `index.html` loads `src/main.tsx`, and `src/ui/App.tsx` picks the page from the address (`src/ui/routes.ts`). Moving between pages is a full page load, so there is no client router.
- **Server:** `server/` is a small Hono app (`server/app.ts`). Each route in `server/routes/*.ts` takes a standard `Request` and returns a `Response`; AI routes stream NDJSON. Model calls happen only there.
  - `pnpm dev` runs Vite on 127.0.0.1:3101 with the server mounted at `/api/*` (`server/vite.ts`). An edit to a route or to `src/ai` takes effect on the next request.
  - `pnpm build && pnpm start` serves `dist/` and the server from one Node process (`server/serve.ts`).
  - Requests are checked by `server/guard.ts` (Host must be this machine; writes must come from this origin; optional launch token).
- **Desktop app:** `electron/main.ts` serves the built UI at `qalam://app` and forwards `/api/*` to the core, a background utility process (`server/core.ts`), over a message port (`server/rpc.ts`). No network port is opened. `vite.desktop.config.ts` bundles both into `out/`, so the installed app needs only Electron.
  - `pnpm desktop` builds and opens it; `pnpm desktop:dev` opens the window on the Vite dev server.
  - `bin/qalam-studio.mjs` is the `npx qalam-studio` launcher.
  - The page's security policy is in `electron/assets.ts`. It allows `unsafe-eval` only because the prototype runner evaluates compiled code (`src/ui/prototype/runtime.ts`).
  - `pnpm dist:mac` packages the Mac app (Apple silicon): `scripts/stage-app.mjs` puts what the installed app loads in `release/app` (out/, dist/, and node-llama-cpp installed by npm, since this package's own `package.json` lists Electron for npx), then electron-builder runs with that folder as its project (`electron-builder.yml`, paths relative to it). The models process and Ask's bridge run the app's binary as Node (`ELECTRON_RUN_AS_NODE`), so never turn that fuse off. The installed app takes the login shell's PATH (`loginShellPath`, `server/claude.ts`) and updates itself from GitHub Releases (`electron/updates.ts`). `.github/workflows/release.yml` builds a tag into a signed, notarized draft release; `homebrew.yml` writes the cask into the tap when a release is published (`docs/releasing.md`).
- **Organizations and products:** pages live under their organization: `/o/<org>` is its home (`src/ui/home/Home.tsx` with `src/ui/org/`), `/o/<org>/d/<id>` a board; `/` and addresses from before (`/d/<id>`) find the organization and move there (`src/ui/App.tsx`). Build links with `projectHref`/`orgHref` (`src/projects/model.ts`), never by hand. A board (`Project.product`) and a source (`SourceRecord.product`) are for one product or the whole organization; products are `products/<slug>.md` and the organization's own context `about.md` (`src/org/context-md.ts`), and Qalam AI reads the board's with `contextFor` (`src/org/context.ts`). A context's goals are `OrgGoal`s, the one that leads first, each with how it's measured, by when and an owner as lines under it; a goal's id is its words' hash (`goalId`) until it's renamed in Qalam, when the file keeps it in a `<!-- qalam -->` comment. A context also has a strategy, what customers use instead and constraints. The server takes a context only through `contextShape`. Sources belong to the organization and list the boards that use them (`boards`); taking one off a board keeps it. A card's quote names its piece (`OstEvidence.piece`, `hub:quote:<id>`).
- **Storage:** an organization is a folder in `~/Qalam` (`QALAM_HOME` moves it; tests and browser checks must point it at a scratch folder). `server/org/` owns it: `codecs.ts` turns projects and sources into readable files, `store.ts` keeps the index, versions (409 on a stale document save) and the folder watcher, `routes.ts` serves `/api/orgs` and `/api/org/:org/*`. The browser side is `src/org/` (client, startup gate, live changes, conflict choice, import from browser storage); the repos in `src/projects/db.ts`, `src/discovery/db.ts`, `src/knowledge/db.ts` and `src/ui/ai/chatDb.ts` go through it.
- **People:** the people an organization hears from are `people/<slug>.md` (`src/org/people-md.ts`; store `listPeople`/`putPerson`, `/api/org/:org/people`; the window's `src/org/people.ts`). A source says who is in it (`SourceRecord.who`: its speakers as people, one person or one segment for all of it, and `saidAt`), set in its Who said it (`src/ui/discovery/WhoSection.tsx`). `voiceOf`/`voicesByQuote`/`tally` (`src/hub/people.ts`) turn quotes into voices, so code counts people and segments behind a need, never quotes; a quote's piece names its person and segment, and its date is when it was said.
- **Evidence strength:** `strengthOf` (`src/hub/strength.ts`, pure) rates what a card rests on by voices (people, or unnamed voices per source and speaker), segments, sources, recency and what's against it; the team's words are never a customer's, and a solution's finished tests count. The card panel shows it (`src/ui/discovery/strength.ts`), Review now reads it, and `runChecks` flags a target resting on thin evidence (`thin-target`).
- **Decisions:** a board's decisions are found by comparing it before and after a change (`decisionsFromDiff` in `src/decisions/diff.ts`), never by instrumenting commands, so every way of changing the board is covered. `src/ui/decisions/recorder.ts` runs that 1.5 s after changes settle, sends what it found to `decisions/<YYYY-MM>.md` (`server/org/store.ts`, Markdown in `src/decisions/format.ts`), asks why on big ones (`WhyPrompt.tsx`) and marks a decision undone when it's taken back. Accepting or discarding Qalam AI's proposals goes through `recordAccepted`/`recordDiscarded`. Adding or rewording a card is not a decision.
- **Search:** the organization's knowledge is indexed as pieces (one fact each: a quote, need, card, assumption, decision, line about a product) with links between them (`src/hub/pieces.ts`). `server/index/` keeps `.qalam/index.sqlite` current from the store's change events (only what changed is written; it can always be deleted and rebuilt) and searches by words (FTS5), meaning (vectors) and links, fused by rank (`server/index/search.ts`); `packFor` fits the result into a token budget with `[k1]` ids (`src/hub/pack.ts`). The embedding model runs in its own process (`server/models/`, node-llama-cpp, downloaded on first use). Change a step only with `pnpm eval:retrieval` before and after: it scores search on a labelled sample organization (`eval/retrieval/`), and its numbers chose today's setup.
- **Calls with the organization's knowledge:** a board's AI calls (draft, extract, synthesize, dump-place) pack what bears on them on the client (`src/org/pack.ts` → `POST /api/org/:org/pack`), leaving out what the call already sends, and pass it as `context` (block, `k` ids, which ids are quotes); routes stay stateless (`withKnowledge`, `knowledgeBlock`, `withPieceReliance` in `src/ai/discovery.ts`). Quotes from other sources load as "visiting" sources (`src/ui/discovery/sources.ts`) so proposals can attach them; accepting puts the source on the board. `recordCall` (`src/ui/discovery/knowledge.ts`) keeps each call's trace: what it was given, and only the cited ids it was sent. No index (Node 22) means no context, and the calls work as before.
- **Topic pages:** one Markdown page per customer need, segment and product (`hub/topics/<slug>.md`, codec `src/hub/topic-md.ts`): We know · We believe · Against · Open questions, and History. Qalam AI files new material into them (`src/org/filing.ts` → `POST /api/topics`, prompt and schema in `src/ai/topics.ts`) after a board reads sources or places a brain dump (`src/ui/topics/filing.ts`), and from the home's Topics tab; each quote sent is marked in its source's `filed`, so it isn't sent again. `sanitizeFiling` (`src/hub/topics.ts`) keeps a line only when every piece it cites was sent and its quoted words and numbers are in them, moves a "We know"/"Against" line resting only on the team's words to "We believe", and never lets Qalam AI rewrite a person's line (it can dispute it). The store applies a filing to the pages as they are (`fileTopics`, one lock with people's edits). Each line is indexed as a `page` piece linked to what it cites (`topicPieces`); packs put page lines found near the top first.
- **Needs a look:** `runChecks` (`src/hub/checks.ts`, pure, no tokens) finds what a team should hear about: Qalam AI's disputes on topic pages, a need customers keep raising that no board has, the same need on two boards, a parked or dropped card new evidence backs, a test running too long, a build on an untested risky assumption, an outcome nobody updates, a page whose pieces are gone. Each notice's key says what it's about and how strong it is, so a dismissed one stays dismissed until it grows. `server/org/notices.ts` runs the checks on request (after the index catches up) and leaves out what's dismissed; dismissals and Review now's findings go in `hub/notices.jsonl`, cards linked as the same need in `hub/relations.jsonl` (append-only, union-merged in Git; links become `same` edges in the index). The last visit is per computer (`.qalam/local`). Review now runs in the core (`server/org/review.ts`, `structured()` in `src/ai/server.ts`): `reviewMaterial`/`sanitizeReview` (`src/hub/review.ts`) keep a finding only when it rests on ids it was sent, its quotes and numbers found in them; a review replaces the last one's findings. The home shows them (`src/ui/org/NeedsALook.tsx`); a board marks its cards (`noticed` in the painter's input) and the card panel says why.
- **Capture:** material added to the organization rather than a board goes through `captureSource` (`server/capture.ts`) in the core: kept as a source with no board, read (the extract call), filed into the topic pages (`fileMaterial`, `src/hub/filing.ts`, which the window's `src/org/filing.ts` also runs with its own dependencies), then placed: one synthesize call over the boards' trees, its answer split by board before `sanitizeSynthesis`, each board's proposals kept in its own file (`hub/placements/<board>.json`, `setPlacements` in `server/org/store.ts`, so accepting on a board never races a capture writing the source). A board finds them through `GET /api/org/:org/placements` and reviews them as its own (`{ kind: "placed" }` in `src/ui/discovery/review.ts`); "Needs a look" says they wait. The calls are described once (`extractCall`, `synthesizeCall`, `topicsCall`) for the routes and the core's `structured()`. Reading files is shared (`src/discovery/ingest/core.ts`, readers passed in): the window reads with pdf.js in a worker and DOMParser, the core with pdf.js's legacy build in-process and mammoth (`server/ingest.ts`). The home's Add reads in the window and posts to `/capture`; the inbox folder (`server/inbox.ts`, started for each store as it opens; the organization opened last opens when the core starts, `openLastOrg`) reads in the core, claims each file by moving it into `inbox/.taking/` (two Qalams on one folder never take a file twice), then moves it to `inbox/added` or `inbox/not-read`. One store per organization per process (`storeFor`), however many requests ask at once.
- **New organization from a brain dump:** "New organization…" opens `/o/<org>/setup` (`src/ui/setup/`; the home offers it while the organization says nothing about itself). What they write about the company (or a web page, read through `/api/fetch-url`) is kept as a brain dump of the organization's, its progress on the source (`setup`, so a reload picks it up). `POST /api/setup` reads it, reads each round of answers (the board's dump helpers, `closeDumpRound`/`applyDumpFollowup`), then proposes the About and the products (`src/ai/setup.ts`). `sanitizeSetup` (`src/org/setup.ts`) keeps a line only when the pieces and answers it cites were sent and its quotes and numbers are in them (an option they picked is their answer), a text field only where it's empty, a new product only under a name they used (`nameHolds`). Accepting writes `about.md` and `products/*.md` (`applyLines`); once every line is settled the core files the dump into the topic pages (`POST /api/org/:org/file`, `fileSources` in `server/capture.ts`: it answers at once, so leaving for a board doesn't stop it; material that's the whole organization's can land on any product's page and segments), and each accepted goal can start a board whose outcome rests on the dump's words. The ids a call gives pieces and cards never show in what Qalam AI says (`readable` in `src/discovery/dump.ts`).
- **Ask the org:** `askOrg` (`server/ask.ts`, `POST /api/org/:org/ask`, NDJSON with activity lines). On Claude Code it runs `claude -p` in the organization's folder with `--tools Read,Grep,Glob --restricted --permission-mode dontAsk --permission-prompts none --strict-mcp-config`, plus the organization's own tools (search, get, decisions) from a small MCP server the core serves over a private socket for that call (`server/mcp.ts`; Claude Code starts a bridge script that joins its stdio to the socket, so no port opens). With an API key it's one call with the organization's knowledge packed. The prompt carries a guide to the folder (pages, boards, sources, decision files) and what search finds first (`src/ai/ask.ts`). `verifyAnswer` (`src/hub/ask.ts`) finds each claim's quotes word for word in the piece or file it names (inside the folder, never `.qalam/`), marks a claim it can't back, and drops a short answer whose quotes or numbers aren't in what backs the claims.
- **Node 24:** development needs it (`.nvmrc`): its SQLite has FTS5, like Electron 45's. On Node 22 the index refuses (`IndexUnavailable`, a 503) and its tests skip.
- **Server-only code:** `src/ai/{server,cli,research,connectors}.ts` read secrets or spawn processes. Browser code must never import them; the build fails if it does (`serverOnly()` in `server/vite.ts`).
- **Settings:** the server reads `.env.local`, then `.env` (`server/env.ts`); a variable already in the environment wins.
- **Model output:** the model proposes and code verifies. Quotes are found word for word, numbers only where the source has them, ids only from what was sent. Keep it that way in new features.
- **Checks:** `pnpm typecheck` and `pnpm test`.
